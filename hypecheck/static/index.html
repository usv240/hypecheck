Spell-check for hype in health press releases.

HypeCheck reads a draft press release next to the paper it reports, flags every sentence that claims more than the study found, has Claude rewrite it, and re-checks the rewrite before anything is published.

How it works

Two models, each doing what it is good at. A small decision model judges; a large language model writes.

Claude on Amazon Bedrock

Tries to publish

The agent takes the draft and calls its publish_release tool.

Strands Decider 2B

Checks every sentence

Before the tool runs, it rates how strong each claim is and compares it with the paper.

Claude on Amazon Bedrock

Rewrites what's flagged

Blocked sentences go back to Claude with the reason; it fixes only those.

Strands Decider 2B

Re-checks, then publishes

The rewrite is checked again. Clean text is published; after 3 failed rewrites a person decides.

See the AWS architecture

Amazon CloudFront in front of an EC2 instance that runs the web app and Strands Decider; the agent runs on Amazon Bedrock AgentCore Runtime and calls Claude through Amazon Bedrock.

Why this matters

Most exaggeration in health news starts in the press release, not the newsroom, and fixing the release fixes the news.

The problem is upstream

Sumner et al. (BMJ, 2014) read 462 UK university press releases next to their papers. A third turned an association into a cause; 36% presented animal results as human; 40% gave advice the paper didn't. When the release exaggerated, 58–86% of the news did too; when it didn't, 10–18%.

Fixing the release works

A randomised trial in 9 real press offices (Adams et al., BMC Medicine, 2019) aligned releases with the evidence: news headlines matched the evidence more often and coverage did not drop. The free human pre-publication review service that did this closed in 2018; nothing automated it.

Limits we measured

  • At the strict threshold it catches 39% of exaggerations (95% CI 30–47%). A press officer still reads the draft.
  • The animal-to-human check is weak (AUROC 0.61 on 45 releases), so it is shown as a hint and never blocks.
  • 563 test pairs give wide intervals; the edge over the published 0.4735 is one run.
  • On the CPU server behind this page, Decider is about six times slower than on a GPU.

For builders: the reusable decision pattern

The gate works for anything that must not say more than its source: summaries, RAG answers, patient leaflets, release notes. decision_pattern/

from decision_pattern import Decider, ClaimFidelityGate, load_threshold gate = ClaimFidelityGate( Decider(), # strands-decider serve … --port 8099 source=lambda: paper_conclusion, # what the text must not exceed tool_name="publish_release", text_arg="text", threshold=load_threshold("calibration.json", "0.1"), # BLOCK -> Guide review_threshold=load_threshold("calibration.json", "0.2"), # REVIEW -> listed, not blocked ) agent = Agent(model="us.anthropic.claude-sonnet-4-6", tools=[publish_release], interventions=[gate])

Calibrate on your own labelled pairs with python -m decision_pattern.calibrate --pairs pairs.jsonl --alpha 0.10. The same gate runs unchanged on a patient-leaflet writer in examples/leaflet_gate.py.

FAQ and glossary

What is Strands Decider 2B?

A small, open decision model from AWS Strands Labs (Apache-2.0). It doesn't write text: you give it some text and a typed question (yes/no, pick one, or score), and it returns an answer with a calibrated probability in a fraction of a second, on hardware you already own.

What does Amazon Bedrock do here?

Bedrock serves Claude, the language model that drives the agent and rewrites flagged sentences. Generating fluent, faithful text is the job a decision model can't do.

Why not just ask Claude whether the release exaggerates?

We measured it: on the same 563 pairs, Claude Haiku 4.5 flagged 44.9% of faithful releases, Sonnet 4.6 29.6% and Opus 4.6 40.0%, and none matched Decider's overall score. Decider with a calibrated threshold flagged 6.7%. Claude also can't be trusted to check its own rewrite, so Decider checks it.

What is "conformal calibration"?

A standard statistical recipe for turning model scores into a threshold with a guarantee. Sort the scores of known-faithful examples and pick the cut-off so that at most 10% of them would be flagged. If new text resembles the calibration set, the same rate holds — we measured 7.7%.

What do BLOCK, REVIEW and OK mean?

BLOCK: above the strict threshold; Claude must rewrite. REVIEW: between the two thresholds; not blocked, but listed for an editor. OK: below both.

Where does it run on AWS?

The web page and Strands Decider run on an Amazon EC2 instance behind Amazon CloudFront. The agent itself runs on Amazon Bedrock AgentCore Runtime (or, if you choose, in-process on the EC2 server), calls Claude through Amazon Bedrock, and reaches Decider through a key-protected HTTPS endpoint whose key lives in AWS Systems Manager Parameter Store.

Is my text stored?

Only the published release is written to the server's outbox; drafts are not kept. Decider runs on our own server; rewrites are sent to Claude on Amazon Bedrock.

Where is the code and the data?

Code, pre-registrations and per-item results: github.com/usv240/hypecheck. Benchmarks: Wright & Augenstein 2021, Yu et al. 2019, and InSciOut (Sumner et al. 2014).
